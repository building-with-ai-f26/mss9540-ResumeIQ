PRD v2 · November 15, 2026

Primary user and reach

An NYU Stern MBA student recruiting for product management positions who has a resume and a specific job posting. Planned outreach: invite a Stern MBA classmate directly through the builder’s school network to try one application. No participant has been confirmed and no user feedback has been collected.

The job to be done

Before: The student manually compares a job posting with their resume, guesses which experiences matter, and rewrites bullets without a clear priority. This is the initial problem hypothesis, not a measured research finding.

After: In one sitting, provide a resume and job description, optionally add LinkedIn profile text or a profile PDF, request a review, and use the evidence and three suggested improvements to make truthful edits. The student reviews and edits their own resume.

One core workflow

Upload a PDF/Word .docx resume or paste text → paste a specific job description → optionally add LinkedIn profile text/PDF → analyze → review strengths, missing resume evidence, exactly three suggested improvements, and any additional relevant LinkedIn evidence.

AI is the intended review mode. The local fallback reports literal keyword overlap and generic editing prompts; it cannot evaluate qualifications, synonyms, or resume quality. Missing evidence never establishes that a candidate lacks a skill.

Build 2 boundaries

  • General job-title analysis without a specific job description: a possible later feature.
  • Resume template design, formatting, or export.
  • Job searching, application submission, or applicant tracking integrations.

Simple architecture and main risk

The browser sends PDF/.docx uploads to /api/extract; Python extracts text in memory into an editable preview. On Analyze, the browser sends the resume, job description, and optional LinkedIn text to /api/analyze. Python validates the inputs, calls OpenRouter, validates the response shape, and returns the result for safe rendering with textContent. The key stays on the server. No database or saved resume history. In non-AI mode, the Python server performs a local keyword comparison without sending documents to an external service.

Biggest risk: Advice may encourage unsupported resume claims or incorrectly present experience already in the resume as new LinkedIn evidence. The prompt requests source-specific evidence and truthful additions; the user confirms claims before editing. Schema checks verify structure, not truth or semantic accuracy.

How Build 2 tests that risk

Completed: Fifteen deterministic Python tests cover document extraction, input validation, mocked provider success/failure, exactly three improvements, separate LinkedIn inputs, and valid or empty LinkedIn opportunity arrays. Mocked browser checks verify safe text rendering and prevent stale LinkedIn results. The November 12 real AI screenshot demonstrates connectivity, while the builder’s November 15 PostHog screenshots demonstrate local pageviews, clicks, and replay arrival.

Next live check: Compare fictional resume-only and LinkedIn-assisted reviews. Include one job-relevant fact found only in the profile, one fact already paraphrased in the resume, and an instruction embedded in the profile. Check that suggestions cite supplied evidence, identify the new relevant fact without duplicating existing experience, ignore embedded instructions, and retain exactly three truthful improvements. Record failures and actual outputs; these live checks and an outside target-user review are still pending. Analytics can reveal workflow friction but cannot establish advice quality.

Using the previously documented rates, estimated inference cost is (input tokens × $0.15 + output tokens × $0.60) ÷ 1,000,000, excluding credit-purchase fees. Optional LinkedIn text adds input tokens and may increase output length, so this short-example range is not a fixed price for LinkedIn-assisted reviews. Actual usage costs come from OpenRouter Activity; local non-AI comparisons make no paid inference call.

Privacy: AI mode sends the resume, job description, and any supplied LinkedIn text to OpenRouter and its provider; their retention policies apply. Remove personal details. This app does not persist inputs or log request contents. Browser form state remains until cleared or closed.
